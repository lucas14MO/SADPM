## 4. Orden del pipeline

**0. Una vez por montaje de cámara**
`capture/calibrate_camera.py` → genera `camera_calibration.json`.

**1. Recorrido**
- Arrancar el GPS Logger **antes** de grabar.
- Grabar:
  ```
  cd capture
  python capture.py --list
  python capture.py --camera N --record
  ```
  Cada sesión crea `recordings/sesion_X/` con `video.mp4`, `frames.csv` y
  `session.json`.

**2. GPX**
Copiar el `.gpx` dentro de cada carpeta de sesión (o pasarlo con `--gpx`).

**3. Detección y georreferenciación**
```
python process_video.py recordings/sesion_X --calibration camera_calibration.json
```
Genera `processed_potholes.json` y `crops/`.

**4. Base de datos y API**
- Linux con GDAL local:
  ```
  cd backend
  docker compose up -d postgis
  python manage.py migrate
  python manage.py runserver 127.0.0.1:8000
  ```
- Windows (Django en Docker):
  ```
  cd backend
  docker compose --profile django up -d --build postgis django
  ```

**5. Importar sesiones** (montando la carpeta **con su mismo nombre**)
```powershell
$SESION = "sesion_AAAAMMDD_HHMMSS"
docker compose run --rm -v "${PWD}\..\capture\recordings\${SESION}:/data/${SESION}:ro" `
  django python manage.py import_processed_potholes /data/$SESION
```
Es idempotente: reimportar una sesión no la duplica.

**6. Mapa**
- `frontend/.env.local`:
  ```
  VITE_USE_MOCK_DATA=false
  VITE_API_BASE_URL=http://127.0.0.1:8000/api
  ```
- `npm run dev` → http://127.0.0.1:5173

`capture/detect.py` (detección en vivo) es opcional; desde esta revisión usa V4 por defecto.

## 5. Umbrales configurables

### Detección y severidad
Definidos en `capture/spm_capture/offline.py` (`SeverityConfig`); se cambian con
opciones de `process_video.py`:

| Opción | Default | Qué controla |
| --- | --- | --- |
| `--conf` | 0.3 | Confianza mínima de YOLO |
| `--min-frames` | 3 | Frames mínimos para aceptar un bache |
| `--roi-horizon` | 0.45 | Descarta detecciones en el 45 % superior de la imagen |
| `--area-light` | 0.001 | Límite leve → moderado (`area_norm`) |
| `--area-critical` | 0.005 | Límite moderado → crítico |
| `--perspective-reference-y` | 0.7 | Fila de referencia para corregir perspectiva |
| `--perspective-exponent` | 2.0 | Intensidad de la corrección de perspectiva |

### Backend
- `--eps-meters 2.5` en `import_processed_potholes`: distancia para agrupar
  detecciones como un mismo bache.
- Ocultamiento por feedback (`backend/potholes/views.py:89`, fijo en código):
  3 reportes de falso positivo o 1 de reparado.
